# 태그 필터링 — 확정 요구사항

## 개요

노트 작성자가 사이드바 상단의 태그 칩을 클릭해 특정 태그가 붙은 노트만 목록에 표시하는 기능이다. 노트 수가 늘어날수록 원하는 노트를 빠르게 찾기 어렵다는 문제를 해결하며, 기존 태그 칩 스타일과 NoteList의 상태 처리 패턴을 그대로 재사용해 UI 일관성을 유지한다.

## 최소 동작 시나리오

1. Actor: 노트 작성자 / 행동: 사이드바 상단의 "react" 태그 칩을 클릭한다 / 결과: "react" 태그를 가진 노트만 목록에 표시된다
2. Actor: 노트 작성자 / 행동: 이미 선택된 "react" 칩을 다시 클릭한다 / 결과: 필터가 해제되어 전체 노트 목록이 다시 표시된다
3. Actor: 노트 작성자 / 행동: 어떤 노트에도 없는 태그 조합을 선택한다 / 결과: "해당 태그의 노트가 없습니다" 메시지가 NoteList 영역에 표시된다

## 결정 사항

| 영역                   | 결정 내용                                                                                    | 이유 또는 근거                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Primary User           | 노트 작성자 본인 — 노트 목록 탐색 중 특정 태그로 좁혀 보는 사람                              | 앱의 단일 사용자이며 태그를 직접 입력한 당사자                                                           |
| 최소 동작 시나리오     | 칩 클릭으로 필터 선택 / 재클릭으로 해제 / 결과 없을 때 인라인 메시지                         | 진입·해제·빈 상태 세 흐름이 최소 완결 단위                                                               |
| 데이터 저장            | `App.tsx` 로컬 상태 `selectedTags: string[]` — 서버 저장 없음                                | 기존 `selectedNoteId`, `isCreating`과 같은 레이어의 UI 상태; 페이지 새로고침 시 초기화가 자연스러운 동작 |
| 경계 조건 — 최대값     | 다중 태그 선택 OR — 선택된 태그 중 하나라도 포함한 노트 표시                                 | 현재 앱 규모에서 결과가 많아지는 OR이 더 유용; 구현 단순                                                 |
| 경계 조건 — 빈 값/중복 | 재클릭 토글로 선택/해제; `selectedTags`가 빈 배열이면 필터 미적용                            | "전체" 버튼 없이 토글만으로 완결; 빈 배열 = 전체 표시로 자연스럽게 처리                                  |
| 에러 처리              | NoteList 내 인라인 텍스트 — "해당 태그의 노트가 없습니다"                                    | 기존 로딩/에러/빈 상태 early return 패턴과 일관성 유지; 토스트·모달은 과한 피드백                        |
| UI 패턴                | 사이드바 상단(노트 카운트 위)에 태그 칩 영역; NoteItem 칩 스타일 재사용; 선택 상태는 색 반전 | `bg-[#dbe4e7] text-[#586064]` 토큰이 이미 정의되어 있음; 선택 시 `bg-[#586064] text-white`로 반전        |
| 향후 확장              | 텍스트 검색 계획 없음 — `selectedTags: string[]` 단독 상태 유지                              | 단순한 구조가 현재 요구사항에 충분; 서버사이드 필터 전환 시 Context API 레이어만 수정하면 됨             |

## 용어 정의 (Ubiquitous Language)

| 용어                  | 정의                                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------------------- |
| 활성 태그(Active Tag) | `selectedTags` 배열에 포함된 태그. 사이드바 칩에서 색 반전으로 표시된다.                                |
| 태그 필터(Tag Filter) | 활성 태그 기준으로 노트 목록을 좁히는 UI 상태. `selectedTags.length > 0`일 때 적용된다.                 |
| 필터 칩(Filter Chip)  | 사이드바 상단에 표시되는 클릭 가능한 태그 칩. NoteItem 칩과 스타일을 공유하나 클릭 상호작용이 추가된다. |
| 전체 노트 표시        | `selectedTags`가 빈 배열일 때의 상태. 별도 "전체" 버튼 없이 모든 태그 토글 해제로 자동 진입한다.        |

## Out of Scope (예비)

- [ ] 텍스트 검색과의 조합 필터 — 이번 구현 범위 아님
- [ ] URL 파라미터 기반 필터 상태 유지(`?tag=react`) — 로컬 상태로 충분
- [ ] 서버사이드 필터링(JSON Server `?tags_like=`) — 클라이언트 필터로 충분
- [ ] AND 로직 다중 필터 — OR로 확정
- [ ] 태그 칩 영역 접기/펼치기 — 태그 수가 많아질 경우 별도 기획
