# Security Review — 커밋 전 타입·보안 점검

## 입력

`$ARGUMENTS`로 이슈 번호를 받는다.

```
/security-review 5
```

---

## 핵심 원칙

① **3개 스캔을 모두 완료한 뒤 분류를 시작한다**
tsc · npm audit · grep 세 가지를 순서대로 전부 실행해 결과를 모은 다음 분류 단계로 넘어간다.
첫 번째 오류를 발견했다고 분류나 수정을 시작하지 않는다.
스캔 도중 수정하면 나머지 스캔 결과와 충돌하거나 같은 파일을 두 번 건드리게 된다.

② **분류는 세 등급으로만 — 중간 등급 없음**
모든 항목은 반드시 "즉시 수정 필요 / 권장 수정 / 무시 가능" 중 하나에 배정한다.
등급 기준:

- **즉시 수정 필요**: 보안 위험 또는 빌드 실패 수준 (빌드가 안 되거나, 민감 정보 노출)
- **권장 수정**: 코드 품질 저하 (타입 안전성 감소, moderate 이하 취약점)
- **무시 가능**: false positive 또는 의도된 패턴 (근거를 반드시 명시)

분류가 모호하면 한 단계 위 등급으로 올린다. 내려서 묻어두지 않는다.

③ **"즉시 수정 필요"만 처리한다 — 나머지는 보고로 끝낸다**
개발자 승인 후에도 "즉시 수정 필요" 항목만 실제로 수정한다.
"권장 수정"과 "무시 가능"은 보고서에 기록하고 처리하지 않는다.
두 등급을 이 단계에서 고치면 커밋 범위가 의도치 않게 넓어진다.

④ **판단이 필요한 모든 항목은 개발자 승인 후 수정한다**
"즉시 수정 필요"로 분류했더라도 개발자 확인 없이 코드를 바꾸지 않는다.
보안 수정은 동작 변경을 수반할 수 있고, npm 패키지 업그레이드는 API 변경을 포함할 수 있다.
스캔 도구가 오탐을 내는 경우도 있다. 최종 판단은 개발자에게 있다.

⑤ **테스트 파일은 수정하지 않는다**
타입 오류나 취약점이 테스트 파일에서 감지되어도 직접 수정하지 않는다.
테스트 파일의 타입 오류는 구현 파일 수정 후 자동으로 해소되는 경우가 많다.
구현 파일을 먼저 고친 뒤 테스트 오류가 남아있으면 개발자에게 보고한다.

⑥ **`npm audit fix --force`는 사용하지 않는다**
`--force`는 major 버전 업그레이드를 자동 수행해 API 변경·빌드 실패를 유발할 수 있다.
`npm audit fix`(force 없이)로 해결되지 않는 취약점은 개발자에게 수동 업그레이드 방법을 안내한다.

⑦ **자동 수정 도구에 의존하지 않는다**
`npm audit fix`, IDE 자동 수정, lint --fix 등 도구가 제안하는 자동 수정을 그대로 적용하지 않는다.
자동 수정은 표면적 오류를 제거하지만 맥락을 모른다 — 의도된 패턴을 지우거나
더 큰 문제를 숨길 수 있다. 도구의 제안은 참고용으로만 보고, 실제 변경은 내용을 확인한 뒤 수동으로 적용한다.

⑧ **승인 없이 자동 수정을 실행하지 않는다**
도구가 자동으로 수정 가능하다고 알려줘도 개발자 승인 전까지 실행하지 않는다.
"fix 가능 여부"는 보고서에 정보로만 기재한다. 실행은 승인 이후다.
승인 전 자동 수정이 실행되면 개발자가 변경 내용을 확인하지 못한 채 커밋에 포함될 수 있다.

⑨ **`.env` 값의 코드 노출은 거의 항상 즉시 수정 필요다**
환경 변수 값이 컴포넌트 렌더링·로그·API 응답 등 클라이언트에 노출되는 코드는
민감 정보 유출로 직결되므로 특별한 반증이 없는 한 "즉시 수정 필요"로 분류한다.
단, `VITE_` 접두사가 없는 변수는 Vite 빌드 시 번들에 포함되지 않으므로 노출 경로를 먼저 확인한다.
"의도된 공개 값"이라는 근거가 명확한 경우에만 등급을 낮출 수 있으며, 반드시 개발자 확인을 받는다.

⑩ **수정 후 반드시 재스캔해서 클린 상태를 확인한다**
수정이 완료되면 1~3단계 스캔을 다시 실행한다.
"고쳤을 것이다"는 가정으로 완료를 선언하지 않는다.
재스캔 결과가 클린해야만 최종 완료로 보고한다.

## 파이프라인

```
[사전 점검]
  0-1. npm test → 현재 테스트 전체 통과 확인 (실패 시 중단)
  0-2. 이슈 본문 읽기 → 도메인 파악 (인증·결제·외부 API 등 보안 민감 영역이면 분류 가중치 상향)
  0-3. .env 파일 존재 여부 확인 → 민감 변수명 목록 파악
  0-4. 스캔 시작 시각 기록 → 재스캔 결과와 비교용 기준점 확보
      ↓
[수집]
  1. npx tsc --noEmit → 타입 오류 목록 수집
  2. npm audit → 취약점 목록 수집
  3. grep으로 .env 변수 직접 노출 여부 확인
      ↓
4. 결과 분류 (즉시 수정 / 권장 / 무시 가능)
      ↓
5. [검토 요청] 개발자 승인 대기
      ↓
6. "즉시 수정 필요" 항목만 처리
      ↓
7. 재스캔 → 클린 상태 확인 후 보고
```

## 단계별 상세

### 사전 점검 0-1 — npm test

```bash
npm test
```

모든 테스트가 통과해야 점검을 시작할 수 있다.
실패 테스트가 있으면 **중단**하고 개발자에게 보고한다:

> **[중단]** 현재 `N`개의 테스트가 실패 중입니다.
> 테스트를 먼저 통과시킨 뒤 security-review를 다시 실행해주세요.

---

### 사전 점검 0-2 — 이슈 본문 읽기 (도메인 파악)

`docs/features/{feature}/issue-$ARGUMENTS.md` 또는 `gh issue view $ARGUMENTS`로 이슈 도메인을 파악한다.
인증, 결제, 외부 API 같은 보안 민감 영역이면 이후 분류에서 가중치를 상향한다.
도메인 판단이 모호하면 사용자에게 묻는다.

---

### 사전 점검 0-3 — .env 파일 존재 확인

```bash
ls .env* 2>/dev/null
```

`.env` 파일이 존재하면 변수명 목록을 파악한다 (값은 읽지 않는다).
파악한 변수명은 3단계 grep 결과와 대조해 실제 민감 변수가 코드에 노출되었는지 판별하는 데 사용한다.
`.env` 파일이 없으면 "✅ .env 없음"으로 기록하고 다음 단계로 넘어간다.

---

### 사전 점검 0-4 — 스캔 시작 시각 기록

```
스캔 시작: YYYY-MM-DD HH:MM
```

이 시각을 기준으로 수집 단계(1~3)의 초기 건수를 함께 기록한다.
7단계 재스캔 결과와 대조해 "이전 N건 → 현재 0건" 형태로 보고한다.

---

### 1단계 — TypeScript 타입 검사

```bash
npx tsc --noEmit 2>&1
```

출력에서 다음을 추출한다:

- 파일 경로와 라인 번호
- 오류 코드 (`TS2345`, `TS2304` 등)
- 오류 메시지 요약

오류가 없으면 "✅ 타입 오류 없음"으로 기록하고 다음 단계로 넘어간다.

---

### 2단계 — npm 취약점 감사

```bash
npm audit 2>&1
```

출력에서 다음을 추출한다:

- 취약점 심각도 (`critical`, `high`, `moderate`, `low`)
- 영향받는 패키지명과 버전
- 취약점 종류 (ReDoS, Prototype Pollution, Path Traversal 등)
- 수정 가능 여부 (`npm audit fix`로 해결 가능한지)

취약점이 없으면 "✅ 취약점 없음"으로 기록하고 다음 단계로 넘어간다.

---

### 3단계 — .env 변수 노출 grep

```bash
grep -rn "process\.env\." src/ --include="*.ts" --include="*.tsx" 2>&1
```

결과를 확인하고:

- 환경 변수가 컴포넌트 내에서 직접 렌더링되는지 확인 (예: `<p>{process.env.API_KEY}</p>`)
- 클라이언트 번들에 민감한 키가 포함될 우려가 있는지 확인
  - `VITE_` 접두사가 없는 변수는 Vite 빌드에서 번들에 포함되지 않으므로 무시 가능
  - `VITE_` 접두사가 붙은 민감 키(SECRET, KEY, TOKEN, PASSWORD 등)는 즉시 수정 필요로 분류

`process.env` 사용이 없으면 "✅ .env 노출 없음"으로 기록하고 다음 단계로 넘어간다.

---

### 4단계 — 결과 분류

수집한 모든 항목을 아래 세 등급으로 분류한다.

#### 분류 기준

| 등급               | 기준                                                                                                                 |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| **즉시 수정 필요** | `critical` / `high` 취약점, TypeScript 컴파일 실패(빌드 불가), 민감 키 클라이언트 노출                               |
| **권장 수정**      | `moderate` 취약점, `TS` 타입 경고(빌드는 되지만 타입 안전성 저하), `low` 취약점 중 실제 익스플로잇 가능성 있는 것    |
| **무시 가능**      | `low` 취약점 중 이 프로젝트에서 익스플로잇 경로가 없는 것, `VITE_` 없는 `process.env` 참조, 테스트 파일 내 타입 오류 |

분류가 모호한 항목은 "권장 수정"으로 보수적으로 처리한다.

---

### 5단계 — 개발자 승인 대기

분류 결과를 전부 출력한 뒤 멈춘다:

> **[검토 요청]** 아래 점검 결과를 확인해주세요.
> "즉시 수정 필요" 항목을 처리하려면 "승인" 또는 "ok"라고 입력해주세요.
> 특정 항목을 건너뛰거나 재분류하려면 번호로 알려주세요.

"즉시 수정 필요" 항목이 없으면:

> **[완료]** 즉시 수정 필요 항목이 없습니다. 커밋 준비가 되었습니다.

---

### 6단계 — "즉시 수정 필요" 항목 처리

승인된 항목만 처리한다. 처리 순서:

1. **TypeScript 타입 오류** — 해당 파일의 타입을 수정한다. 테스트 파일이면 건너뛰고 보고한다.
2. **npm 취약점** — `npm audit fix`(--force 없이)로 해결 가능하면 실행한다. 불가능하면 개발자에게 수동 업그레이드 가이드를 제공한다.
3. **민감 키 노출** — 해당 렌더링 코드를 제거하거나 서버 사이드로 이동하는 방향을 개발자와 협의한다.

각 항목 처리 후 변경 내용을 간단히 기록한다.

---

### 7단계 — 재스캔 및 최종 보고

처리가 완료되면 1~3단계를 다시 실행한다.

```bash
npx tsc --noEmit 2>&1
npm audit 2>&1
grep -rn "process\.env\." src/ --include="*.ts" --include="*.tsx" 2>&1
```

재스캔 결과를 0-4에서 기록한 초기 건수와 대조해 최종 보고를 출력한다.

```
스캔 시작: YYYY-MM-DD HH:MM
타입 오류:  이전 3건 → 현재 0건
취약점:     이전 2건 → 현재 0건
.env 노출:  이전 1건 → 현재 0건
```

## 보고 형식

**타입 검사**

| 파일               | 라인 | 오류 코드 | 메시지               | 등급      |
| ------------------ | ---- | --------- | -------------------- | --------- |
| `src/api/notes.ts` | 42   | TS2345    | Argument of type ... | 즉시 수정 |

**취약점**

| 패키지   | 심각도 | 종류  | fix 가능 | 등급      |
| -------- | ------ | ----- | -------- | --------- |
| `semver` | high   | ReDoS | ✅       | 즉시 수정 |

**.env 노출**

| 파일               | 라인 | 변수명                | 등급                    |
| ------------------ | ---- | --------------------- | ----------------------- |
| `src/api/notes.ts` | 3    | `process.env.API_URL` | 무시 가능 (VITE\_ 없음) |

**처리 결과**

| 항목                         | 처리 방법        | 결과    |
| ---------------------------- | ---------------- | ------- |
| TS2345 `src/api/notes.ts:42` | 타입 캐스트 수정 | ✅ 해소 |

**재스캔 결과**

```
tsc: ✅ 오류 없음
npm audit: ✅ 취약점 없음
.env 노출: ✅ 없음
```

**다음 단계 제안**

- 권장 수정 항목이 남아있으면 별도 이슈로 다루기를 권장한다
- 클린 상태라면 커밋 진행을 안내한다
